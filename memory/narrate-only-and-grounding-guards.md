# Narrate-only tightening and grounding guards

- 2026-10-09 — Narrate-only tightening. Diagnosis: the earlier "VMI contradiction" was a regex false positive on a sloppy sentence, and most "invented evidence" was real data from other loan sections (only the FZD "included in HMDA case" item was truly fabricated). Fixes: the model sees only its own case; it writes three prose fields only; evidence/data-quality/change blocks and scope notes are code-owned; narratives are fact-checked, retried once, then replaced by a code-written narrative. Granite 3B seeded, 8 agents x seeds 42/7: heuristic accuracy 92.5 / 88.8 (was ~84), 2 of 8 narratives fell back to the deterministic text on seed 42 and 1 of 8 on seed 7 (contradiction watchdog; since narrowed to Compliant results only because "fails to exceed the spread" is normal on Not Applicable).
- 2026-11-07 — Response templates and the report (plans/archive/response-templates). The model rephrases code-written examiner paragraphs and writes only a 150-word report summary; both are checked and replaced by code on failure. Three things cost time: (1) the drafts must travel in the tool result (`examiner_paragraph_drafts`), because in `tool_mode: model` the decision exists only after the model's own tool call, and the drafts are stripped from the stored decision; (2) protected tests pin the narrative request shape (prefix plus a JSON object keyed by the roles, in the Anthropic/OpenAI live validators), the narrative payload and the CLI file write, so the report is assembled inside the narrative role and the narrative prompt carries a `---USER-MESSAGE-PREFIX---`; (3) test fakes written before the `examiner_paragraphs` contract answer without paragraphs and cause a retry on any case with findings, so a fake must echo the drafts (see `echo_drafts` in `tests/test_agent_runner.py`). Suites that import siblings by bare name need `tests/` on `sys.path` to run as `python3 -m unittest tests.test_x`.
- 2026-11-07 — Auditor exemption. Live Haiku 5.5 runs: the auditor fell back to the code-written narrative in 3 of 8 role/phase runs and no other role did, because its Non-Compliant result summarizes other regimes and a narrative that says "TRID is compliant" matched the "claims compliance" check. The check is now skipped for the auditor only (`cross_regime`, set in `agents/runner.py`); every single-regime role, and the Compliant-result check on the auditor, are unchanged.

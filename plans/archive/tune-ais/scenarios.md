# Tune AIs: scenarios

Generated by `python3 -m benchmarks.floor_sweep --scenarios-md plans/archive/tune-ais/scenarios.md`; do not edit by hand. Synthetic data only.

Each domain role runs `sample` and its own regime's `fail` and `gap` case. The auditor and the narrative role run `sample`, `fail:all` and `gap:all`; their inputs (the other roles' results) are built by code only, so they do not depend on the model being tuned. Per role and rung 1 or 2 that is scenarios × 2 tool modes × 3 repetitions; rung 0 is deterministic (one run per scenario).

Choice rule: for each regime, in the fixture order of `tests/response_fixtures.py` (base cases, then each leaf dropped, then each boolean flipped, then value changes), the first case with a `not_satisfied` finding is `fail`, and the first with an `unable_to_determine` finding and no `not_satisfied` finding is `gap`. The spec names `tests/fixtures/*/scenarios.json`, but only YBS has one; the other regimes' cases come from the same fixture source the response-templates sweep used (the cases each evaluator suite already uses).
